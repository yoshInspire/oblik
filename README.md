# Студия «Верста» — сайт

Next.js 16 (App Router, Turbopack) + Tailwind CSS v4. 94 страницы, собранные из семантического ядра.

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
npm run build
```

## Развёртывание на сервере

Требуется Node.js 20.9 или новее. Первый раз:

```bash
git clone https://github.com/oblikfeo/oblik.git
cd oblik
cp .env.example .env        # заполнить домен и токены
npm ci
npm run build
npm start                   # слушает 3000, за ним нужен nginx
```

Обновление. `git pull` сам по себе ничего не меняет — приложение
собирается заранее, поэтому после каждого обновления нужна пересборка
и перезапуск процесса:

```bash
git pull
npm ci                      # только если менялся package-lock.json
npm run build
# перезапустить процесс: pm2 restart versta / systemctl restart versta
```

Процесс держать под pm2 или systemd — `npm start` в отдельной сессии
умрёт вместе с ней. Nginx проксирует на `127.0.0.1:3000` и раздаёт HTTPS.

Каталог `data/` создаётся при первой заявке и в репозиторий не входит.
Он должен быть доступен процессу на запись и попадать в резервные копии —
там лежат обращения.

## Как устроен проект

Контент — источник истины. Страницы, навигация, карта сайта, хлебные крошки и микроразметка
собираются из одного реестра, поэтому рассинхронизироваться не могут.

```
seo/markers.json           маркерные запросы: падежные формы, синонимы, привязка к URL
scripts/seo/build-core.mjs расширение → чистка → кластеризация → карта релевантности
  ↓
seo/keywords.tsv           2708 фраз: фраза | URL | интент | тип | оценка частотности
seo/clusters.json          94 кластера, по одному на страницу
seo/report.txt             объём, распределение, риски каннибализации
  ↓
content/pages/*.json       контент под каждый кластер (h1, title, description, блоки, FAQ)
lib/content.ts             реестр: getPage, childrenOf, trailFor, resolve
app/[...slug]/page.tsx     один маршрут рендерит все 91 внутреннюю страницу
```

Добавить страницу — значит добавить объект в `content/pages/*.json` и подключить файл
в `lib/content.ts`. Маршрут, ссылки в подвале, sitemap и хлебные крошки появятся сами.

## Архитектура сайта

| Уровень | Раздел | Страниц |
|---|---|---|
| Хабы | `/uslugi/` `/tehnologii/` `/otraslyam/` `/goroda/` `/voprosy/` | 5 |
| Услуги L2 | `/uslugi/<услуга>/` | 17 |
| Услуги L3 | `/uslugi/<услуга>/<подуслуга>/` | 27 |
| Технологии | `/tehnologii/<стек>/` | 11 |
| Отрасли | `/otraslyam/<ниша>/` | 12 |
| Города | `/goroda/<город>/` | 7 |
| Вопросы | `/voprosy/<вопрос>/` | 11 |
| Отдельные | `/` `/stoimost/` `/about/` `/contacts/` `/privacy/` | 5 |

**Гео.** Москва — регион привязки сайта, её запросы остаются на страницах услуг.
Остальные города вынесены в `/goroda/`, чтобы страницы услуг не конкурировали сами с собой
в региональной выдаче. Гео-страницы требуют привязки региона в Яндекс.Вебмастере — без неё
они почти не работают.

## Цены

Цен на сайте нет намеренно. Ни прайса, ни ставки, ни вилок «от». Вместо этого — `/stoimost/`
с разбором того, что влияет на смету. Разметка `Offer` с ценой не ставится: фиктивная сумма
в JSON-LD — прямой путь к санкциям поисковых систем.

`npm run seo:check` падает, если в контенте появится сумма.

## Проверки

```bash
npm run seo          # пересобрать ядро из маркеров
npm run seo:check    # покрытие, метатеги, уникальность текста, отсутствие цен
npm run test:form    # прогон формы заявки по HTTP без JavaScript
```

`seo:check` ловит главное — шаблонный контент: считает предложения, повторяющиеся между
страницами. Норма — ноль. На текущем контенте: 2914 предложений, 0 повторов.

## Заявки

Форма работает без JavaScript (прогрессивное улучшение через Server Actions).
Заявка сначала пишется в `data/leads.jsonl`, затем отправляется в Telegram и на вебхук —
если внешний сервис недоступен, обращение не теряется.

Переменные окружения:

```
NEXT_PUBLIC_SITE_URL=https://example.ru
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
LEAD_WEBHOOK_URL=
```
